What each piece of evidence proves. Text captures are generated by scripts and are included in this repository.
Browser screenshots are **not included yet**; the table below lists the ones planned, so they can be
taken by hand later and saved in `docs/screenshots/` with the exact file names shown.

## Terminal captures (already generated)

| File | Produced by | What it proves |
|---|---|---|
| `docker-ps.txt` | `docker ps` snapshot | The architecture: 4 BFT orderers, peers for Org1 and Org2, CAs, one CouchDB per peer. It also shows the extra Org3 peer, its CouchDB and its CA, which exist only for the privacy proof. So the counts there are 3 peers, 4 CAs and 3 CouchDB instances, not 2, 3 and 2. |
| `rejections.txt` | `scripts/reject-demo.sh PRD-901` | The rules live in the chaincode: wrong org, duplicate id, skipped stage and wrong-org stage move are all rejected, and the history lists only the 2 successful transactions. Rejected requests leave no trace on the ledger. |
| `org3-privacy.txt` | `scripts/org3-proof.sh` | Org3 cannot read `supplychannel`: its peer has joined no channels, a query fails with "channel 'supplychannel' not found", and the orderer answers FORBIDDEN when Org3 asks for a block. Org1 and Org2 read the same product successfully. |

## Optional terminal screenshots

`docker ps`, `scripts/reject-demo.sh PRD-902` and `scripts/org3-proof.sh`, and save them as
`06-docker-ps.png`, `07-rejection-demo.png` and `08-org3-refusal.png`.

## Regenerating the text captures
```bash
scripts/reject-demo.sh PRD-902 > docs/evidence/rejections.txt      # needs a NEW product id each time
scripts/org3-proof.sh           > docs/evidence/org3-privacy.txt
docker ps ...                                                       # see first line of docker-ps.txt
```
